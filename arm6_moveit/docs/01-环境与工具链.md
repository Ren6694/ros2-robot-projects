## 1. 目标与硬约束

| 约束 | 落地方式 |
|---|---|
| WSL 工作目录只有两个：`~/embed_sim_ws`（STM32/QEMU）、`~/ros2_ws`（本项目） | 本项目全部读写只发生在 `~/ros2_ws`，产物回传到 Windows 侧工程目录 |
| 禁止修改 `/etc`、`/root` 等系统敏感目录 | 不写 `/etc/apt/sources.list.d/`、不改 `/opt/ros`；ROS 用官方 apt 包，不 `pip install`、不 `sudo rm`；`~/.bashrc` 只在阶段一已有的 env 段里追加，本项目改用**显式 source 脚本**（见 §5），连 `~/.bashrc` 都不碰 |
| 所有 Linux 命令用 bash | 远端一律 `ssh ros2vm "cd ~/ros2_ws && bash scripts/xxx.sh"`，无 PowerShell |
| 图形窗口用 WSL 内置 XFCE 渲染 | 交互式 rviz 走 `DISPLAY=:0`；**可复现截图**走 Xvfb（原因见 [06-可视化与截图](06-可视化与截图.md)） |
| 不动 WSL 原有 SSH 免密配置 | 全程复用已存在的 `ros2vm` 主机别名，未增删 `authorized_keys`/`sshd_config` |
| API 调用设额度上限 | 长任务一律"一条命令跑完并落盘日志"，避免反复交互；单次远端命令自带 `timeout`（bringup 寿命 240 s、接口探测 60 s） |

**发行版选择**：装的是 **ROS 2 Jazzy**（Ubuntu 24.04 noble 上唯一可用的官方 ROS 2 发行版）。
简历与文档统一表述为 **「ROS 2 Jazzy（与 Humble 同源 API）」**——本项目用到的接口
（`MoveGroup`/`ExecuteTrajectory` action、`moveit_msgs` 的 `MotionPlanRequest`、
`MoveItConfigsBuilder`、ros2_control 的 JTC）在 Humble 上写法一致，只有
`moveit_commander` 的可用性差异，见 §6。

## 5. 环境准备脚本 `scripts/ros_env.sh`

所有远端脚本第一行都是 `source scripts/ros_env.sh`，它做四件事：

```bash
set +u
source /opt/ros/jazzy/setup.bash
[ -f "$WS/install/setup.bash" ] && source "$WS/install/setup.bash"
set -u
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST     # 单机仿真，避免广播到虚拟网卡
[ "${1:-}" = gui ] && export DISPLAY="${DISPLAY:-:0}"
echo "ros_env: ROS_DISTRO=$ROS_DISTRO DISPLAY=${DISPLAY:-<none>} DOMAIN_ID=${ROS_DOMAIN_ID:-0}"
```

三个非显然的点：

1. **`set +u` 包住 source**：colcon 生成的 `install/setup.bash` 引用了未导出的
   `${COLCON_TRACE}`，在 `set -u` 下直接 `unbound variable` 退出。脚本要 `set -euo pipefail`，
   所以只能在 source 这一段临时关掉 `-u`。
2. **`DISPLAY` 只在 `gui` 模式下兜底**：无头回归脚本不应该有 `DISPLAY`，否则
   rviz/Octomap 会误连 WSLg 的 X 服务端（06 里那个"截图全黑"就是这么来的）。
3. **末行打印环境**：日志开头就能看出这次跑在什么环境下，跨次比较时先对齐环境再对齐数据。

> 实测到的弃用告警：`ROS_LOCALHOST_ONLY=1` 在 Jazzy 仍生效，但每个节点启动都会打
> `[WARN] ROS_LOCALHOST_ONLY is deprecated ... Use ROS_AUTOMATIC_DISCOVERY_RANGE`。
> 已改用新变量。旧日志里那批 WARN 是历史版本脚本留下的，见 `logs/bringup_20260916-234501.log:8-13`。

## 6. ★ 接口选型：为什么不用 `moveit_commander`

这是本项目最重要的一次"先测量再写代码"。三条独立证据链：

```bash
apt-get install -y ros-jazzy-moveit-commander
#   E: Unable to locate package ros-jazzy-moveit-commander
apt-cache search --names-only commander | grep -i moveit
#   （空）

ls /opt/ros/jazzy/lib/python3.12/site-packages | grep -i moveit
#   moveit_configs_utils   moveit_msgs        # 没有 moveit 这个包

dpkg -L ros-jazzy-moveit-ros-planning-interface | grep '\.so$'
#   只有 3 个 C++ .so —— MoveGroupInterface 没有 Python 绑定
```

结论：**Jazzy 的 apt 安装里 `MoveGroupCommander`（旧 moveit_commander）和 `MoveItPy`
两套 Python 包装都不可用**。于是点位节点直接用
`rclpy` + `moveit_msgs/action/MoveGroup`（`plan_only=True` 规划）
+ `moveit_msgs/action/ExecuteTrajectory`（执行），
接口细节全部从安装介质读出来：

```bash
# ros2 interface show 会因 RobotState 自引用无限递归，必须直接读 .msg 源文件
ls /opt/ros/jazzy/share/moveit_msgs/msg/
```

字段级结论与完整构造代码见 [05-点位控制节点与运动日志](05-点位控制节点与运动日志.md) §2。
运行期实测的 action/topic/service/node 清单在 `logs/moveit_interfaces_20260916-230333.txt`
（由 `bash scripts/probe_moveit_interfaces.sh` 生成），字段定义摘录在 `logs/moveit_interface_types.txt`。

## 7. 工作空间布局

```
~/ros2_ws/                       # WSL 侧（构建与运行）
├── src/
│   ├── arm_description/         # URDF/Xacro + ros2_control 硬件声明 + rviz 单模型显示
│   ├── arm_moveit_config/       # MoveIt 配置包（SRDF/关节限位/运动学/控制器/launch）
│   └── arm_demo/                # 点位控制节点 + 运动日志 + 绘图/比较脚本的消费方
├── install/  build/  log/       # colcon 产物
├── scripts/                     # 与 Windows 侧同源，由 sync.sh 单向推过来
├── logs/                        # 所有运行证据（构建日志、bringup、motion jsonl/csv）
└── artifacts/                   # 图与截图，回传 Windows

<工程目录>\20260916-ros2-moveit-arm\   # 唯一真源
├── src/ scripts/ docs/ logs/ artifacts/
```

**同步方向严格单向**：`bash scripts/sync.sh`（Windows → WSL，只推 `src/ scripts/`，
并顺手 `sed` 掉 CRLF、`chmod +x`）；`bash scripts/fetch_artifacts.sh`（WSL → Windows，
只拉 `logs/ artifacts/`）。
理由写在 `scripts/update_collisions.sh` 头部：WSL 的 `src/` 只是副本，
任何工具（如 `collisions_updater`）的输出都落到 `artifacts/`，就地覆盖 `src/`
会在下一次 sync 时被无声冲掉。
