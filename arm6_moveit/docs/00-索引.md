# ROS 2 + MoveIt2 六轴机械臂仿真 — 文档索引

一个 **8 自由度**（6 轴臂 + 双平行指）机械臂的完整仿真闭环：自己写的 URDF/SRDF →
MoveIt 配置 → `ros2_control` mock hardware → 自研点位节点直连 `MoveGroup` action →
逐点位运动日志（JSONL/CSV）→ 曲线图与 rviz 截图证据 → 14 个带机器可读结论行的验收脚本
（判据自测有两个入口：`selftest_embed_gate.sh` 与 `check_visual_envelope.py --selftest`）。

运行环境：WSL2 Ubuntu 24.04 + **ROS 2 Jazzy**（简历口径：**ROS2 Jazzy（Humble 同源 API）**）、
MoveIt 2.12.4、ros2_control 4.48.0 / JTC 4.42.1。工作空间 `~/ros2_ws`，3 个包：
`arm_description`、`arm_moveit_config`、`arm_demo`。

> **为什么要有一份索引**：本项目所有量化结论都必须能反查到一个真实文件。
> 文档里不允许出现"实测表明"而后继没有任何日志/图片/行号支撑的句子 ——
> §4 的表就是这条约定的账本。

## 3. 工程入口

```bash
source scripts/ros_env.sh                     # 任何手工调试前：DISTRO/DISPLAY/DOMAIN/发现范围
bash scripts/sync.sh                          # Windows → ros2vm:~/ros2_ws（源码，单向）
ssh ros2vm "cd ~/ros2_ws && bash scripts/build_ws.sh"              # BUILD-RESULT
ssh ros2vm "cd ~/ros2_ws && bash scripts/check_limits.sh"          # CHECK-RESULT
ssh ros2vm "cd ~/ros2_ws && bash scripts/run_waypoint_demo.sh full"  # 主回归：DEMO-RESULT
ssh ros2vm "cd ~/ros2_ws && bash scripts/run_waypoint_demo.sh plan-only"  # 提交前快速版（~25s）
ssh ros2vm "cd ~/ros2_ws && bash scripts/capture_rviz.sh"          # 截图证据：CAPTURE-RESULT
bash scripts/fetch_artifacts.sh               # WSL → Windows（logs/ 与 artifacts/，单向）

# 跨运行回归（在 WSL 里跑；判据输出直接留档成证据文件）：
#   16 份 CSV → 12 份进比对（plan-only 由脚本自己认出并剔除）
python3 scripts/compare_motion_runs.py --col track_err_rad --exclude 234501,231533 \
        motion_2026*.csv motion_rviz_2026*.csv          # → COMPARE-RESULT PASS (0,1,0,2)

# 双工作空间同机并发（第一判据 = 时间窗重叠率，不是"我同时启动了"）
ssh ros2vm "cd ~/ros2_ws && bash scripts/check_concurrency.sh 3 20260917-005248"  # CONCURRENCY-RESULT
# 上面那条 ADC 半边关卡的正/负对照（不起栈、~1 s：改过 embed_gate.py 或抽取规则后必跑）
ssh ros2vm "cd ~/ros2_ws && bash scripts/selftest_embed_gate.sh"                  # EMBED-GATE-SELFTEST
```

不带 `--csvs` 时脚本自己匹配 `logs/motion_*.csv`，所以要在 `~/ros2_ws` 下跑；
证据文件一律**在 WSL 里生成**再拉回（Windows 侧重定向会写 CRLF，跨平台 diff 会全行标红，07 §2.6）。

同步方向严格单向：Windows 侧是**唯一真源**，`src/` 只 push；`logs/`、`artifacts/` 只 pull。
就地覆盖会在下一次 `sync.sh` 时被无声冲掉 —— 这就是 `update_collisions.sh`
把候选写到 `artifacts/` 而不是直接改 `config/arm6.srdf` 的原因（04 §3.2）。

> 顺带一条**两阶段不一致**的口径（避免下次有人在远端 `grep docs` 扑空）：本项目
> `sync.sh` 的 `ITEMS=(src scripts)`，**不同步 `docs/`**，所以远端 `~/ros2_ws/docs/` 是个空目录
> （实测 `ls` 为空；成因未追，不影响任何判据）；阶段一的 `ITEMS` 含 `docs`，远端有一份可就地 grep 的副本。
> 两边文档的**真源都永远是 Windows 侧**，要改就在 Windows 改（阶段一为兼容远端核对，
> 文档里用 `~/embed_sim_ws/docs/…` 的绝对路径，见作品集 `01` §2）。

## 7. 维护约定（这几张表本轮真的漂过）

1. **新增一次回归运行** → 更新 05 §7 的运行表与"共 N 次"计数、05 §6.1 的 Δt 表与样本数、
   07 §4 的计数（用表前那条命令）、本索引 §5 的规模表。四处都要动，漏一处表格就开始互相矛盾。
2. **新增/改名一个脚本结果行** → 本索引 §2 与 02 §3 两张表都要登记（07 §1 的一分钟自检也要）。
3. **产物改名** → 候选/中间产物文件名里必须带能区分它们的量（`arm6_20k.srdf` 的教训见 04 §3.4）。
4. **文档里的每个数字** → 必须能在 §4 那张表里落到一个文件（最好带行号）。做不到就删掉那句话。
5. **结论落不了盘，就补做一次取证**，而不是保留"实测表明"四个字。
   本轮 06 §1 的 WSLg 结论就只有终端摘录：重跑一次（`logs/wslg_rootwindow_probe_20260917-004912.txt`）
   才发现当初引的 `5120x1600` 复现不出来 —— 那是 root 窗口宽度**本来就不是稳定量**
   （WSLg 挂几个显示决定它），稳定的只有 `std=0.00`。补取证顺带把一个假规律筛掉了。
   ★ 同一轮里还揪出一条**引用了不存在文件**的行（`logs/serial_20260917-0058*.csv`，
   两侧工作空间都没有）：写引用时顺手 `ls` 一下，别凭印象拼文件名。
6. **负载/并发类结论必须写明重叠率**（`overlap_frac=… / 被保护时长`），"我同时启动了"不算证据。
   本轮据此撤回了 `005801`（实际只重叠 2 s 且全在 bringup）：撤回说明留在结论旁边，不删数据。
7. **判据用到的名单只留一处真源。** `--exclude` 早期在三个调用点各抄一份，加一次运行就要改三处；
   现在 plan-only 由 `compare_motion_runs.py` 自己从盘上认出，人只保留"缺陷留证"那一份名单。
8. **脚本打印的量必须被判据消费**（`check_concurrency.sh` 的教训）：旧版印三条 `EMBED` 采集、
   却只把最新一次送去比对，退出码也没接 —— `embed_ok=3/3` 于是成了"跑完 3 次"而不是"比过 3 次"。
   规则：**每印一个 `X=…` 就要求有一个判据读它**；只印不判的字段必须自己写明 `(not-gated)`。
9. **因果句要么有判据，要么改成"机制未测"。** 本轮撤掉两条（"bringup 高峰扰动 ADC"、
   "CPU 抢占造成 3.04 ms"），两条都是顺手写的、都没有判据；归因的正解是**与一份无关归档互比**。
10. **表格里能整段贴输出就别手抄。** §6.1 那张 Δt 表原本是我照终端重排的，多一句"列序和脚本不同
    别对着读"的补丁；现在直接贴 `compare_*.txt` 的原样输出，列身份由 `DT cols=` 自己说。
11. **批量改完 Markdown 要全量体检，不能只查改过的那篇。** 本轮（09-17）用脚本改表格时，
    缺陷恰恰落在**没打算改**的本索引 §2：`max|err|` 里两个竖线未转义 ⇒ 那一行被拆成 6 列，
    而同一文件还带着 169 个 CRLF（成因没有逐次追踪，只能是某次以文本模式写盘；其余 18 篇全是 LF）。
    两者都是**呈现层出错、数值不变**，人眼读源码看不出来。所以规矩是：任何正则/批量编辑之后，
